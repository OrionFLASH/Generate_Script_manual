# Скрипт HTTP Traffic Logger (`HTTP_Traffic_Logger.js`)

## Назначение

Отдельный **фоновый инструмент** для DevTools Console (не встроен в скрипты выгрузки). Режимы:

1. **Запись** — перехват `fetch` / `XMLHttpRequest` и (опционально) действий UI на странице.
2. **FULL** — отдельный дамп: снимок HTML/CSS + весь HTTP из буфера (без UI и без тел бинарных файлов).
3. **Play** — воспроизведение UI-лога («плёнка»), сбор HTTP, ошибки/slow, накопление **тест-лога**.

Панель не блокирует сайт: можно ходить по страницам стенда, пока идёт запись или Play.

---

## Типы файлов

Имена: `httplog_<хост>_<метка>_<YYYYMMDD_HHMMSS>.<ext>`

| Метка | Файл | Откуда | Когда сохраняется |
|-------|------|--------|-------------------|
| `http` | `…_http_….log` | Запись | Всегда при **⬇ Сохранить** (состав по тоглам) |
| `json` | `…_json_….json` | Запись | Если тогл JSON |
| `ui` | `…_ui_….log` | Запись | Если тогл UI |
| `full` | `…_full_….log` | FULL | По **⬇ Сохранить FULL-дамп** |
| `test` | `…_test_….log` | Play | Только по **⬇ Сохранить тест-лог** |

**Хост в имени:** `location.hostname` без `www.` и без TLD (`.ru`, `.com`, `.net`, …).  
Пример: `https://salesheroes.sberbank.ru` → `salesheroes.sberbank`.

Несколько файлов записи качаются **с паузой ~0.45 с** (иначе Chrome часто оставляет только первый). При запросе браузера разрешите сайту несколько загрузок.

## Запуск

1. Открыть стенд в браузере → DevTools → Console.
2. Вставить содержимое `Script/HTTP_Traffic_Logger.js` → Enter.
3. Повторная вставка заменяет предыдущую панель и снимает старый перехват.

### Типовой сценарий записи

1. Вкладка **Запись** → отметить тоглы состава `.log` / JSON / UI.
2. **▶ Старт** → работать в UI сайта → **⏹ Стоп**.
3. **⬇ Сохранить** → `http` (+ `json` / `ui` по тоглам).
4. При необходимости вкладка **FULL** → **▶ Старт FULL** → Стоп → **⬇ Сохранить FULL-дамп**.

### Типовой сценарий Play (регресс по плёнке)

1. Вкладка **Play** → **📂 Загрузить лог UI** (`httplog_*_ui_*.log`).
2. При необходимости настроить паузы / порог slow.
3. **▶ Play** (при записи нельзя; **⏹ Стоп** прерывает текущий прогон).
4. Можно **повторить Play** или загрузить другой UI-лог — результаты **копятся** в одном буфере.
5. **⬇ Сохранить тест-лог** → один файл `_test_` со всеми прогонами до очистки.
6. **Очистить тест** — сброс накопления.

## Интерфейс

### Общее

| Элемент | Назначение |
|---------|------------|
| Вкладки **Запись** / **FULL** / **Play** | Три режима; запись и Play одновременно нельзя |
| **—** / **×** | Свернуть в мини-бар / закрыть и восстановить родные `fetch`/`XHR` (скрыты во время записи и Play) |
| Заголовок | Перетаскивание панели |

### Вкладка «Запись»

| Элемент | Назначение |
|---------|------------|
| **▶ Старт / ⏹ Стоп** | Включение записи. Во время записи панель **сжимается**: только Стоп + статистика |
| **Маска ПДн** | Маскирует ПДн в `.log` / FULL / UI (JSON без маски) |
| Тоглы «Что писать в файлы» | Состав `http`-лога + флаги JSON / UI |
| Фильтр URL | Только на экспорт `http`-лога |
| **⬇ Сохранить** | `http` всегда; `json`/`ui` по тоглам |
| **Очистить** | Сброс буферов записи и тест-лога Play |

#### Тоглы состава (по умолчанию)

| Тогл | Файл | По умолчанию |
|------|------|--------------|
| Заголовки запроса / ответа | `http` | вкл. |
| Payload запроса | `http` | вкл. |
| Тело ответа | `http` | выкл. |
| Тайминг | `http` | выкл. |
| Ответы сервера JSON | `json` | вкл. |
| Клики UI | `ui` | выкл. |

### Вкладка «FULL»

Отдельный режим дампа страницы (не заменяет «Запись»).

| Элемент | Назначение |
|---------|------------|
| **▶ Старт FULL / ⏹ Стоп** | Своя запись HTTP для дампа (**без UI-кликов**); панель сжимается на вкладке FULL |
| Описание | Что попадёт в `_full_.log` |
| Статистика | Размер буфера HTTP, оценка бинарных, число stylesheets |
| **⬇ Сохранить FULL-дамп** | Один файл `httplog_<хост>_full_*.log` (после Стоп) |

**Содержимое FULL:**

1. Мета страницы (URL, title, viewport, UA)
2. Снимок HTML (без панели логгера)
3. CSS: inline `<style>` + CSSOM stylesheets; при CORS — попытка взять тело из HTTP-буфера
4. Списки `link[rel=stylesheet]`, `script[src]`, preload
5. Performance resource entries
6. Весь HTTP из буфера: headers + payload + body + timing (**без UI**)
7. Тела **бинарных** ответов (image/font/pdf/zip/…) не пишутся — пометка `SKIP_BINARY`

**Ограничения FULL:** classic `<script src>` / картинки, грузящиеся браузером минуя `fetch`/`XHR`, в HTTP-буфер не попадут (останутся в Performance/DOM-списках). Cross-origin CSS без CORS и без попадания в буфер не восстановить.

Сценарий: вкладка **FULL** → **▶ Старт FULL** → работа на стенде → **⏹ Стоп** → **⬇ Сохранить FULL-дамп**.

### Вкладка «Play»

| Элемент | Назначение |
|---------|------------|
| **📂 Загрузить лог UI** | Парсит `_ui.log`; не очищает тест-буфер |
| Пауза / ожидание сети / порог slow | Параметры темпа и детекции медленных запросов |
| **▶ Play / ⏹ Стоп** | Прогон плёнки; компакт-панель во время Play |
| **⬇ Сохранить тест-лог** | Выгрузка `_test_` |
| **Очистить тест** | Сброс тест-накопления |

Во время Play панель компактная: Стоп + статистика.

## Связь id (запись)

Общий **`sessionId`** на сессию записи.

| Поле | Смысл |
|------|--------|
| `sessionId` | Сессия |
| `eventId` | Сквозной id (`evt_<session>_N_http\|ui`) |
| `eventSeq` | Порядковый номер события |
| `corrId` | Метка записи (`httplog_…_N` / `…_ui_N`) |
| `afterUiEventId` | У HTTP: `eventId` последнего UI-события до запроса (эвристика) |
| `id` | Локальный счётчик внутри HTTP или UI |

Пример: клик `eventId=…_5_ui` → `POST …` с `afterUiEventId=…_5_ui`.

В тест-сессии Play `sessionId` вида `play_<ts>_<rnd>`; у HTTP есть `playStepIndex`.

### Накопление тест-лога

- Первый Play открывает тест-сессию (очищает HTTP-буфер под Play).
- Повторные Play и смена UI-файла **добавляют** шаги (маркеры `run#N`) и HTTP в тот же буфер.
- Автоскачивания нет.
- **⬇ Сохранить тест-лог** пишет один `_test_` со всем накопленным.
- **Очистить тест** / **Очистить** (Запись) сбрасывают накопление.

### Содержимое `_test_.log`

1. Мета + сводная статистика (в т.ч. `runCount`)
2. **STEPS** — все шаги всех прогонов (`run#`, ok/skip/fail/noise)
3. **FINDINGS** — ошибки / slow / miss
4. **HTTP** — полный дамп трафика тест-сессии
5. **EMBEDDED_JSON** — блок `<<<JSON` … `JSON>>>`

Анализ HTTP после шага: `http_status`, `body_error` (`success:false` и т.п.), `slow`, `ui_miss`.

## Запись UI: что пишется

События (capture, кроме панели логгера):

- `click` — closest button/a/input/label/`role=…`/`[id*=-option-]`; SVG → родительская кнопка; оболочка `dialog` **не пишется**
- `change` / `submit`

В лог: стабильный `selector`, `name`/`value`/`role`/`inOverlay`/`reactSelectOption`, `text`, `href`, `xpath`, `detail`.

## Анализ типичных пропусков Play (по логам salesheroes)

На прогоне `ui_…015922` → `test_…020037`: **25 ok / 3 skip**.

| Пропуск | Почему | Что сделано в скрипте |
|---------|--------|------------------------|
| `button…px-16` «Редактировать» | Предыдущий клик по иконке без текста попал в «чужую» `button.cursor-pointer.transition`; меню/модалка не открылась | Слабые селекторы без текста → **xpath раньше CSS**; ожидание портала/overlay перед шагами с xpath `/html…/body…` |
| `div#react-select-6-option-2` | Id react-select **меняется** между сессиями | Запись/поиск по **тексту option** (`TOP_MANAGER`), не по `#react-select-N-option-M` |
| `dialog#dialog` (весь диалог) | Случайный клик по оболочке модалки — шум | Такие клики **не пишутся** и при Play помечаются `skip/noise` |

Модалки на стенде: `#dialog` / `dialog`, сезон/фильтры внутри; меню профиля — портал в `body`; react-select — `[id*="-option-"]` / `[role=option]`. Радио с `name=_r_*` нестабильны — опираемся на **`value`** (`SEASON_2025_1`).

Также не пишем клики по SVG `path`/`rect` (поднимаем до `button`).

HTTP findings в том же тесте (`success=false` на like, status 0) — ответы бэка/обрыв, не пропуск UI.

## Play: поиск элементов и модалки

Порядок: **value (radio) → option-text → name → href → aria → текст в overlay → xpath (для слабых CSS) → selector → text**.

Перед шагом внутри модалки/поповера/option — ожидание overlay до ~4 с (`#dialog`, `[role=dialog]`, `#popover`, radix popper).

Накопление тест-лога без автосохранения — см. выше.

## Форматы файлов записи

### JSON ответов (`http_traffic_responses_v3`)

Без маски ПДн. Поля связи + `request`/`response` (как в экспорте Записи).

### `http`-лог

Секции по тоглам: REQUEST/RESPONSE HEADERS, PAYLOAD, BODY, timing.

### `full`-лог

Секции: PAGE META, HTML SNAPSHOT, STYLESHEETS/CSS, DOM ASSET LINKS, PERFORMANCE RESOURCES, HTTP TRAFFIC (полный дамп; `SKIP_BINARY` для файлов).

### `ui`-лог (фрагмент)

```
--- ui#13 … [click]
page https://…/admin/…?tab=notifications
selector input[name="enableColleagues"][type="checkbox"]
tag input type=checkbox
name enableColleagues
checked false
xpath …
detail {"checked":true,"value":"on",…}
```

## Ограничения (честно)

**Сеть**

- Не видит запросы вне страницы (другие расширения, часть Service Worker); WebSocket не пишется.
- `blob:` / `data:` пропускаются; тела > ~2 MB обрезаются (`truncated`).
- Буфер HTTP ~5000, UI ~8000 записей.
- Автозаголовки браузера (Cookie и т.п.) в перехвате могут быть неполными.

**UI / Play**

- Не 100% покрытие: canvas, закрытый Shadow DOM, кастомные dropdown без DOM-событий, иконки без текста/aria, нестабильные React-id (`_r_…`).
- Старые UI-логи с только Tailwind-селекторами Play чинит частично (достаёт `name` из селектора); для лучшего replay перезапишите UI новой версией скрипта.
- `afterUiEventId` — эвристика, не строгая причинность.
- Fuzzy-клики по кнопкам без текста могут попадать «не туда».

## Конфиг `CFG` (в скрипте)

| Ключ | Смысл |
|------|--------|
| `MAX_BODY_LEN` | Мягкий лимит тела (~2 MB) |
| `MAX_ENTRIES` / `MAX_UI_EVENTS` | Размеры буферов |
| `DEFAULT_MASK` | Маска ПДн по умолчанию |
| `PLAY_STEP_DELAY_MS` | Пауза между шагами Play |
| `PLAY_SETTLE_MS` / `PLAY_SETTLE_MAX_MS` | Ожидание тишины сети |
| `PLAY_SLOW_ABS_MS` / `PLAY_SLOW_FACTOR` | Пороги slow |
| `PLAY_FIND_TIMEOUT_MS` | Ожидание появления элемента (~5 с) |
| `PLAY_OVERLAY_TIMEOUT_MS` | Ожидание модалки/поповера (~4 с) |
| `FILE_PREFIX` | `httplog_` |
