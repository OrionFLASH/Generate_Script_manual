# Скрипт выгрузки новостей community (`News_Community_Export.js`)

## Назначение

На странице выбранного окружения gamification (стенд `PROM/PSI/IFT-SB/IFT-GF`, контур `ALPHA/SIGMA`) из консоли DevTools выполняются **POST**-запросы:

`POST {origin}/bo/rmkib.gamification/proxy/v1/news`

Куки берутся из сессии вкладки (`credentials: "include"`).

## Режимы payload

### 1. Базовый (status × businessBlock)

Последовательный обход комбинаций **newsStatus × businessBlock**. Пример тела:

```json
{
  "newsStatus": "published",
  "businessBlock": "KMKKSB",
  "pageNum": 1
}
```

**Обязательно** выбрать ≥1 `newsStatus` и ≥1 `businessBlock` — иначе выгрузка не запускается.

Списки допустимых значений и паузы задаются в блоке **`NEWS_CFG`** вверху скрипта (удобно править):

| Ключ `NEWS_CFG` | Назначение |
|-----------------|------------|
| `STATUS_OPTIONS` | варианты `newsStatus` (по умолчанию отмечен `published`) |
| `BUSINESS_BLOCK_OPTIONS` | варианты `businessBlock` (по умолчанию `KMKKSB`) |
| `TAG_OPTIONS` | теги `NEWS_TYPE` (по умолчанию все выкл., опционально) |
| `CUSTOM_TAG_TYPE` | тип своих тегов (`TEXT`) |
| `PAYLOAD_GAP_MS` / `PAGE_GAP_MS` | паузы 500 / 100 мс |
| `RETRY_MAX` / `RETRY_PAUSE_MS` / `CONSECUTIVE_FAIL_ABORT` | повторы при ошибке (3×2000 мс); стоп после 2 подряд |
| `CSV_DATA_KEYS` | колонки CSV после параметров запроса |
| `ORIGINS` / `NEWS_PATH` | стенды и путь API |

### 2. С опциональным фильтром по тегам

Теги **не обязательны**. Если выбран ≥1 тег `NEWS_TYPE` **или** задан свой TEXT-тег — в payload каждой комбинации `status × block` дополнительно добавляется `newsTagList`:

```json
{
  "newsStatus": "published",
  "businessBlock": "KMKKSB",
  "newsTagList": [
    { "tagType": "NEWS_TYPE", "tagCode": "bestPractice" },
    { "tagType": "TEXT", "tagCode": "Гарантии" }
  ],
  "pageNum": 1
}
```

Теги `NEWS_TYPE` (по умолчанию все выключены): `bestPractice`, `achievement`, `publication`.  
Свои теги — textarea (разделители `;` и перевод строки), в запрос уходят как `{ "tagType": "TEXT", "tagCode": "…" }`.  
Несколько тегов = **один** `newsTagList` на каждую комбинацию status×block.

## Пагинация

В ответе `body.page`: `total`, `isLast`, `num`.  
Для каждой комбинации скрипт запрашивает страницы `pageNum = 1 … total` (остановка также по `isLast`).

Если по комбинации ответа нет (HTTP-ошибка, нет JSON, `success: false`) — запись в журнал и переход к **следующей** комбинации. Частично полученные страницы сохраняются.

## Паузы (панель)

| Параметр | По умолчанию | Назначение |
|----------|--------------|------------|
| Пауза между payload | **500** мс | между разными комбинациями · поле на панели |
| Пауза между страницами | **100** мс | внутри одной комбинации · поле на панели |
| Повтор при ошибке | **2000** мс × **3** попытки | поля на панели (`RETRY_*` — дефолты в `NEWS_CFG`) |
| Макс. страниц | **0** (= все) | лимит `pageNum` внутри комбинации; `3` → не больше первых 3 страниц |

### Повторы и аварийная остановка

1. Ошибка HTTP или содержимого JSON → пауза `RETRY_PAUSE_MS` (2000) и повтор, до `RETRY_MAX` (3) **попыток на один pageNum**.
2. После исчерпания попыток — **пропуск** страницы и переход к следующей (`pageNum+1`), пока есть страницы по `page.total` / лимиту.
3. Аварийная остановка — только если **два подряд** запроса исчерпали попытки **и** следующей страницы уже нет. Уже загруженное сохраняется; `exportMeta.fatalError`.
4. Итоговый цвет статистики: **зелёный** только без ошибок; при пропусках — **красный** (`готово с ошибками` / `ошибка — сохранено`).

## Статистика на панели

Живой блок: фаза, `newsStatus`, `businessBlock`, **теги**, страница `pageNum/total`, прогресс, **собрано** (уже выгруженные строки), **`newsCount`** (общее число новостей комбинации из `body.newsCount`), ошибки.

## Выгрузка JSON

Кнопка **«Загрузить → JSON»** сохраняет объект:

| Ключ | Содержимое |
|------|------------|
| `exportMeta` | стенд, контур, origin, режим, selection, счётчики |
| `comboResults` | результат по каждой успешной комбинации (`merged` комбинации) |
| `pages` | сырые ответы API по страницам |
| `merged` | объединённый ответ по всем комбинациям |

## Выгрузка CSV

Кнопка **«Выгрузить JSON + CSV»** — те же POST, затем JSON и CSV с одним таймштампом.

Имя CSV: `…_news.csv`. **Одна строка = одна новость.** Разделитель полей — **`;`** (`NEWS_CFG.CSV_DELIMITER`).

Колонки:

1. Параметры запроса: `newsStatus`, `businessBlock`, `pageNum`, `total`
2. Данные новости: `newsId`, `newsType`, `summary`, `newsText`, `newsItemStatus` (поле `newsStatus` новости), `createDate`, `updateDate`, `plannedDate`, `date`, `businessBlocks`

Пока **не** включаются поля 6–9: `tbCode`, `gosbCode`, `contests`, `rewards` (список колонок — `NEWS_CFG.CSV_DATA_KEYS`).

Массивы/объекты (`businessBlocks` и т.п.) сериализуются в JSON-строку. Колонка `businessBlock` всегда заполняется из параметров запроса (теги его не заменяют).

## Панель

- Выбор стенда и контура, автоопределение по `window.location.origin`
- Компактная панель действий **вверху** прокрутки: ⬇ JSON · ▦ JSON+CSV · ⏹ Стоп · ✕ Закрыть
- Компактная сетка: **Статус *** / **Блок *** / **Теги (опц.)** (+ свои TEXT)
- Тайминги на панели: паузы payload/страниц, **макс. страниц** (0 = все), пауза повтора, число попыток, префикс файла
- Статистика: фаза, status, block, **теги**, стр., прогресс, **собрано**, **newsCount**, ошибок
- **Журнал работы + Trace** — сразу под блоком параметров, без пустого зазора; блок растягивается по оставшейся высоте панели
- Кнопка **Стоп** — прерывает после текущего POST и сохраняет уже загруженные данные в JSON/CSV
- Кнопка **Закрыть** неактивна во время выгрузки
- Trace (DevToolsTrace)

### Валидация запуска

| Поле | Правило |
|------|---------|
| Статус | ≥1 обязательно |
| Блок | ≥1 обязательно |
| Теги | можно не выбирать |

При нарушении — сообщение в журнале, красная статистика, запросы не уходят.

Сводка HTTP: [Справочник_скрипты_HTTP_запросы_и_последовательность.md](Справочник_скрипты_HTTP_запросы_и_последовательность.md) (§ 6).
