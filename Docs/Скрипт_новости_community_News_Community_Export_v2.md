# Скрипт News community v2 (`News_Community_Export_v2.js`)

## Назначение

Скрипт добавляет отдельную модалку с вкладками для массовых операций по новостям community:

- **Выгрузка** новостей (обновлённый блок старого сценария `POST /proxy/v1/news`)
- **Создание** новостей (`newsCreate`)
- **Смена статуса** `draft ↔ published` (`newsUpdate`, `method: "patch"`)
- **Редактирование (каркас)** (`newsUpdate`, `method: "put"`)

Основной сценарий — загрузка JSON из файла, показ компактного списка кандидатов и отправка только отмеченных элементов после подтверждения.

## API и окружение

- Стенды: `PROM`, `PSI`, `IFT-SB`, `IFT-GF`
- Контуры: `ALPHA`, `SIGMA`
- Куки: `credentials: "include"` (сессия текущей вкладки)

Запросы:

1. `POST /bo/rmkib.gamification/proxy/v1/administration/news/newsCreate`
2. `POST /bo/rmkib.gamification/proxy/v1/administration/news/newsUpdate` (patch/put)

## Вкладка «Выгрузка (старый блок)»

Выгрузка приведена к паритету с исходным `News_Community_Export.js`:

- кнопки **⬇ JSON**, **▦ JSON+CSV**, **⏹ Стоп** (зеркало общей кнопки панели);
- цветной блок **Статистика** (фаза / status / block / теги / стр. / прогресс / собрано / newsCount / повторов / ошибок);
- компактный выбор status / businessBlock / тегов (+ custom TEXT);
- пагинация с ретраями; паузы / попытки / диапазон **Стр. с…Стр. по** / аварийный стоп — из **общего блока панели**;
- в payload уходит только выбранный диапазон `pageNum` (например, 10…20);
- при `body.page.isLast === true` следующий `pageNum` **не** запрашивается (даже если «Стр. по» ещё не достигнут);
- при аварии / **Стоп** / исключении JSON (и CSV) всё равно сохраняются из **успешно** загруженных страниц; ошибочные ответы в файл не попадают; имя файла с суффиксом `_partial`.
- корректный **merge всех страниц** в `comboResults[].merged` + полный массив `pages[]`;
- CSV: одна строка на новость, разделитель `;`.

Интерфейс вкладки повторяет цветовую схему исходного скрипта (градиентный фон панели, тона статистики idle/run/retry/done/stop).

## Общие паузы, ретраи и Стоп

Над вкладками — общий блок настроек для **всех** операций (выгрузка / создание / статусы / редактирование):

| Поле | Назначение |
|------|------------|
| Пауза операций, мс | Между элементами пакета (create/status/edit) и между комбинациями выгрузки |
| Пауза страниц, мс | Между `pageNum` внутри комбинации (выгрузка и загрузка для редактирования) |
| Стр. с | Начальный `pageNum` (по умолчанию `1`) |
| Стр. по | Конечный `pageNum` включительно; `0` = до последней страницы API. Пример: с `10` по `20` — только эти страницы |
| Пауза повтора, мс | Перед повторной попыткой при ошибке |
| Попыток | Число попыток одного запроса |
| Стоп после N ошибок подряд | Аварийная остановка пакета |

Кнопка **⏹ Стоп** на панели (и на вкладке выгрузки) прерывает текущий пакет после текущего запроса. Одновременно может идти только одна операция.

## Вкладка «Создание»

Поддерживает два основных формата входного JSON:

1. **Шаблонный формат**:

```json
{
  "createItems": [ ... ]
}
```

2. **Формат выгрузки** (`News_Community_Export.js` / v2):
   - `pages[].body.timePeriod[].news` — **все страницы**;
   - `comboResults[].merged.body.timePeriod[].news`;
   - `comboResults[].pages[].body...` (если есть);
   - `merged.body.timePeriod[].news`.

Разбор идёт по всем `body`/`pages`, не только по первой странице. Дедупликация по `newsId`.

В компактном списке выбора (создание / редактирование):

- колонки: **NewsType**, заголовок (**до 50** символов), число **тегов**, **коды**, авторы, лидеры, ID;
- коды по `newsType` / `NewsType`:
  - `individualAchievement` / `achievement` → `rewardCode` (несколько — с новой строки);
  - `tournamentAchievement` → `tournamentCode` (несколько — с новой строки);
  - если кодов нет — `—`.

Минимальные критичные поля для создания:

- `type` (из допустимого набора)
- `createdBy` (если в файле пусто — подставляется значение из интерфейса/дефолт)

### `createdBy` по умолчанию

Если `createdBy` отсутствует в файле/записи, используется значение по умолчанию:

- `00673892`

Его можно изменить вручную в поле на вкладке «Создание» перед разбором/отправкой.

### Режим «болванка: без leaders и authors»

На вкладке «Создание» есть чекбокс:

- **«Болванка: без leaders и authors»**

Если режим включён:

- `leadersList` и `authorsList` принудительно отправляются как `[]`;
- значения из файла / исходных данных при отправке игнорируются;
- в таблице выбора счётчики авторов/лидеров **не меняются** (показывают данные из файла);
- перед созданием в confirm есть пометка о режиме болванки.

`createdBy` при этом по-прежнему берётся из файла или из поля по умолчанию (`00673892`).

## Вкладка «Статусы»

Источник данных:

- JSON-файл (`statusItems`, массив, либо экспортный JSON с новостями)
- или список `newsId` из текстового поля

Для каждого элемента отправляется:

```json
{
  "newsId": "...",
  "status": "published",
  "method": "patch"
}
```

Аналогично поддерживается обратный переход в `draft`.

Перед отправкой:

- обязательная проверка `newsId` и `status`;
- есть явная кнопка **«Выбрать файл JSON»**;
- подтверждение в интерфейсе;
- запись результата в отдельный JSON-файл.

## Вкладка «Редактирование (каркас)»

Реализован поток с двумя источниками данных:

1. **Из файла**: загрузка `updateItems` из JSON.
2. **С сервера**: загрузка текущих новостей через `POST /proxy/v1/news` (выбор status/block, лимит страниц), затем выбор записей в таблице.
3. Для выбранных записей формируется payload редактирования (`method: "put"`).
4. Отправка в `newsUpdate`.

Предусмотрен экспорт шаблона файла редактирования для дальнейшего расширения логики.
Для загрузки из файла используется явная кнопка **«Выбрать файл JSON»**.

Минимально критичное поле для редактирования:

- `newsId`

## Компактный список выбора перед отправкой

Перед выполнением операций из файла отображается краткая таблица:

- Тип новости
- Заголовок (кратко)
- Количество авторов
- Количество лидеров
- ID новости

Все элементы отмечены по умолчанию.

### UX-улучшения выбора

Для вкладок с таблицей кандидатов добавлены:

- поле быстрого поиска (по типу / заголовку / ID);
- кнопки массовых действий:
  - «Отметить всё»
  - «Снять всё»
  - «Отметить в фильтре»
  - «Снять в фильтре»
  - «Очистить загруженное» (сброс списка кандидатов из файла)
- индикатор:
  - всего записей
  - записей в текущем фильтре
  - выбранных записей

На вкладке **«Создание»** кнопки сгруппированы (Файл / Выбор / Запуск), цветные по роли; активность зависит от наличия JSON в поле, загруженного списка, фильтра и числа выбранных (кнопка создания показывает счётчик и блокируется без выбора / во время операции).

## Примечания по надежности

- Если в выбранных данных есть ошибки по критичным полям, запросы не выполняются.
- Все массовые операции требуют подтверждения.
- Результаты выполнения сохраняются в JSON (`*_result_*.json`) с payload и ответами API.
- Создание / статусы / редактирование / выгрузка используют общие паузы, ретраи, аварийный стоп и кнопку **Стоп**.
- При `success: true` без `body` (типично для patch/put статуса) ответ считается успешным; для create дополнительно проверяется `body.objectId`.
